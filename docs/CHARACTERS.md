# Персонажи: задачи 4–6

Один React-компонент читает риг из JSON. Встроенные buyer/advisor переведены на тот же формат; ветвления по имени персонажа в рисунке больше нет. После миграции все 26 контрольных PNG существующего ролика совпали побайтово.

Риг содержит упорядоченные слои, группы головы и рук, точки вращения, варианты выражений, открытых/закрытых глаз и четыре состояния рта. Поддерживается сидячая фронтальная постановка, небольшой наклон и покачивание головы, моргание, кивок, поднятие руки, пожатие плечами и телефон. Поворот головы здесь — ограниченное 2D-движение; новый ракурс и скрытая анатомия не восстанавливаются. Движение рта следует измеренной огибающей записи и обозначено `approximate/amplitude`, без фонемной артикуляции и выдуманных word timings.

## Из эскиза в риг

Пользователь присылает обычные PNG/JPEG по шаблону персонажа. Готовые слои от пользователя не обязательны. Агент или художник размечает видимые части и варианты лица в `character_recipe`; worker собирает подготовленный пакет. Это управляемая разметкой подготовка, не автоматическая нейросетевая сегментация рисунка.

1. Создать библиотечный `character`, импортировать `front` и `three_quarter`, при необходимости `expressions`, `hands`, `mouths`, `pose_reference`.
2. Получить `get_character_recipe_template`. Пример координат соответствует только [синтетическому листу](../examples/character-cutout/sheet.png); их нельзя автоматически переносить на другой рисунок.
3. Подготовить recipe: `rig`, `missing_details`, `generated_details`, `notes`. Разметить полигоны частей, их размещение на холсте 380×560, pivots головы и рук, состояния глаз/рта/выражений. Для `cutout` указывать `source_role`, `polygon` в пикселях исходника и `target: [x,y,width,height]` в координатах персонажа.
4. Вызвать `set_character_recipe(item_id, expected_revision, recipe)`, затем `prepare_library_item` с новой ревизией и ключом идемпотентности.
5. Прочитать пакет через `toon://library/{id}/revisions/{revision}/package`. Worker проверяет границы полигонов по измеренным размерам, заменяет роли на неизменяемые ссылки ассетов и рассчитывает bounding boxes. Исходные пиксели не меняются; подготовленные слои представлены масками и размещением поверх оригиналов. Векторные элементы допустимы как декларативная геометрия с явным описанием дорисовок.

Если рука перекрыта туловищем, нет закрытых глаз или нужного рта, недостающие детали нужно перечислить. Нельзя выдавать вырезанный фрагмент за восстановленную скрытую часть. `missing_details` и недостающие группы/варианты блокируют готовность рига. `generated_details` сохраняются в recipe и превращаются в предупреждения для просмотра. Автоматической дорисовки и облачных запросов здесь нет; самостоятельное AI-извлечение/дорисовка из произвольного рисунка не реализовано.

Без recipe сохраняется прежний режим исходного пакета с `render_supported:false`. С ним можно работать и публиковать его как материалы, но нельзя использовать вместо персонажа в ролике.

## Проверочный речевой ролик

Импортировать настоящую речевую WAV/MP3-запись длительностью 4–12 секунд через `register_asset`, указать точный текст записи. Вызвать:

~~~json
{
    "item_id": "content_...",
    "expected_revision": 7,
    "audio_asset": { "asset_id": "asset_...", "version": "1.0.0" },
    "transcript": "Точный текст короткой записи.",
    "idempotency_key": "vasya-test-v1"
}
~~~

Инструмент `start_character_test` ставит обычное устойчивое render-задание. Оно продолжает работать после закрытия MCP, отменяется через `cancel_job`, проверяет snapshot/hash и публикует артефакты только после проверки MP4. Платные TTS-запросы запрещены в этом сценарии.

Запись повторяется в трёх сценах: общий план и два крупных. Проба показывает шесть эмоций, моргание, кивок, покачивание головы, поднятие руки, пожатие плечами и телефон. Финальное время вычисляется из измеренной записи и пауз; речь не обрезается. Телефон — проверочный реквизит, а не настоящий интерфейс приложения. Проверка уровня аудио не является распознаванием речи: оператор обязан подать речь и проверить соответствие transcript прослушиванием.

Получить `get_artifacts(job_id)`: MP4, cover, контрольные PNG, timeline/project, captions и `character-review.json`. В последнем художественный просмотр и прослушивание явно остаются `pending_operator`. Смотреть лицо на общем/крупном плане, края масок, плечи/локти, перекрытия, движения и все состояния рта.

Для публикации рига нужны успешный проверенный MP4 **того же package hash** и `publish_library_item(..., review_approved:true, review_note:"Что просмотрено и прослушано")`. Сам факт успешного рендера не означает художественное одобрение. Изменение recipe или материалов требует новой подготовки и новой пробы; опубликованная версия остаётся неизменной.

В обычном DraftProject использовать `character_id = item_id` и опубликованную `version`. Сцены, события и реплики ссылаются на этот же ID. Проект и снимок задания фиксируют конкретную версию рига, а export ZIP включает риг в timeline и исходные изображения для масок. Проба неопубликованного пакета использует служебную версию `0.0.0`; её project.json предназначен для диагностики пробы, для обычного проекта заменить версию на выпущенную.

## Контракты и ограничения

- [Риг](../contracts/character-rig.schema.json), [recipe](../contracts/character-recipe.schema.json), [пример recipe](../templates/library/character-recipe.json).
- Только группы, path/ellipse/circle/rect и cutout; произвольные SVG/HTML/JS, URL, обработчики событий и CSS не принимаются. У импортированных файлов сохраняются allowlist, проверка декодирования и hash.
- До 512 узлов, 256 KiB рига, 128 точек в полигоне; canvas 380×560, готовый фильм 1080×1920/30 fps.
- Декорации, клонирование и назначение голосов — следующие задачи 7–11.

## Проверки

~~~powershell
# Требуется Pillow; создаёт только наш оригинальный синтетический лист:
python scripts/create-character-fixture.py examples/character-cutout/sheet.png
# Реальные речевые offline fixtures готовятся отдельно через scripts/prepare-fixtures.ps1.
./scripts/acceptance.ps1 -Characters
./scripts/acceptance.ps1 -Library
./scripts/acceptance.ps1
~~~

Синтетический лист проверяет механизм разметки и анимации, а не сходство с реальным человеком. Речь для теста — явно обозначенная локальная SAPI fixture Microsoft Irina. Художественная приёмка реальных пользовательских эскизов, живой TTS и клонирование не подтверждаются этим тестом.
