# Библиотека контента

Библиотека принимает описания и исходные материалы персонажей, декораций и голосов. Она хранит неизменяемые ревизии, собирает проверяемый пакет и позволяет опубликовать его **локально**. Публикация не отправляет данные в GitHub, ElevenLabs или другую облачную систему.

Риги персонажей, подготовка разметки эскизов и проверочные ролики описаны в [CHARACTERS.md](CHARACTERS.md). Пакет исходников без recipe сохраняет `render_supported:false`, в том числе после публикации. Персонаж с подготовленным ригом, проверочным MP4 и одобренным просмотром может быть опубликован как render-compatible версия; его ID/version доступны обычному DraftProject и `get_catalog(kind="characters")`. Декорации с разметкой слоёв, позициями героев, камерами и проверочным MP4 описаны в [ENVIRONMENTS.md](ENVIRONMENTS.md). Импорт и анализ образца, клонирование через ElevenLabs, аудиопроба и привязка к персонажу описаны в [VOICES.md](VOICES.md). `get_catalog(kind="library")` и `list_library_items` показывают библиотеку материалов.

## Шаблоны

- [Персонаж](../templates/library/character.json): внешний вид, характер, палитра, поза. Обязательны `front` и `three_quarter`. Дополнительные листы: `expressions`, `hands`, `mouths`, `pose_reference`. Один PNG/JPEG на роль; рекомендуемый размер одного вида 2048×2048, одинаковые пропорции.
- [Декорация](../templates/library/environment.json): место действия, освещение, палитра, расположение персонажей, перекрытия. Обязателен `wide`; дополнительно `layout`, `foreground`, `detail`. Рекомендуемый вертикальный холст 2160×3840. Персонажи и точный интерфейс телефона не должны быть нарисованы на фоне.
- [Голос](../templates/library/voice.json): имя говорящего, язык, манера речи, произношение, отдельные флаги согласия на клонирование и облачную отправку. Обязателен `sample` — WAV/MP3 одного говорящего без музыки. Образец остаётся локально даже при `cloning_consent:true`. Облачный профиль и его привязка создаются отдельным процессом после подготовки и явного разрешения на отправку.

Шаблоны доступны через `get_submission_template(kind)` и resource `toon://library/templates/{kind}/1.0.0`. Ответ содержит роли и актуальные лимиты сервера. Контракт: [library-submission.schema.json](../contracts/library-submission.schema.json), resource `toon://library/submission-schema`. Неизвестные поля, включая поле API-ключа, отклоняются. Не помещайте секреты в свободные текстовые описания.

Действуют лимиты `register_asset`: по умолчанию 25 MiB на файл, 12 MP на изображение, 120 секунд аудио. Изображения/аудио декодируются и проверяются; ZIP, SVG, HTML, исполняемые файлы и пути вне `TOON_IMPORT_ROOTS` не принимаются. Симлинки и reparse points запрещены. Повторный импорт заменяет роль в новой ревизии, сохраняя предыдущую.

## Сценарий добавления персонажа

1. Получить `get_submission_template(kind="character")`, заполнить объект `submission`. `rights_confirmed:true` означает подтверждение оператором права использовать материалы, а не автоматическую юридическую проверку.
2. Вызвать `create_library_item(submission=...)`. Сохранить `item_id` и `revision`. Одинаковые отображаемые имена допустимы: операции адресуются по ID.
3. Вызвать `import_library_material(item_id=..., expected_revision=..., role="front", source_path=..., note=...)`, затем аналогично для `three_quarter`. Путь абсолютный, внутри настроенного корня импорта. После каждого изменения использовать новую возвращённую ревизию.
4. Запустить `prepare_library_item(item_id=..., expected_revision=..., idempotency_key=...)`. MCP немедленно возвращает job; worker запускается отдельно. Повтор исходного запроса с тем же ключом возвращает тот же job даже после завершения. Изменение запроса при том же ключе даёт `IDEMPOTENCY_CONFLICT`.
5. Опросить `get_job(job_id)`, затем прочитать `get_library_item(item_id)`. Успешное выполнение проверки означает состояние `review`, а не публикацию. Изучить `preparation.errors`, `warnings`, `ready_for_publication`.
6. Получить `get_library_materials(item_id, revision)`: проверенные по хешам ссылки на исходные изображения/запись. Пакет доступен через `toon://library/{id}/revisions/{revision}/package`. Просмотреть изображения или прослушать образец. Автоматическая проверка не подтверждает сходство персонажа, композицию, содержание речи или пригодность голоса для клонирования.
7. Вызвать `publish_library_item(item_id, expected_revision, version="1.0.0", review_approved=true, review_note="Что проверено")`. Пустой комментарий или отсутствие явного подтверждения отклоняется. Подтверждение передаётся после соответствующего просмотра/прослушивания.

Для декорации и голоса процесс тот же. Отсутствующие обязательные материалы и неподтверждённые права — ошибки пакета с указанием поля; они блокируют публикацию. Анализ голосового образца сохраняет отдельный `voice_analysis`: запись короче 10 секунд, чрезмерная тишина или перегрузка блокируют клонирование. Это не блокирует хранение исходного пакета. ASR, автоматическая оценка сходства и удаление шума не выполняются.

Запуск worker из корня:

~~~powershell
dotnet src/Toon.Worker/bin/Debug/net10.0/Toon.Worker.dll
~~~

Закрытие MCP не отменяет job. Отмена — через `cancel_job`. После отмены, технической ошибки или истечения аренды библиотека при следующем чтении/изменении возвращает запись в `draft` новой ревизией, сохраняя `last_error` и ID задания. Повторный запуск требует нового ключа и актуальной ревизии. Отмена и фиксация результата синхронизированы транзакцией.

## Ревизии, версии и состояния

| Состояние | Действия |
| --- | --- |
| draft | Описание/материалы редактируются |
| preparing | Worker проверяет снимок; редактирование заблокировано |
| review | Проверка доступна; исправление создаёт draft и сбрасывает review |
| published | Версия выпущена; обновление создаёт новый draft |
| archived | История/версии доступны; update начинает новый draft |

`revision` — целое число истории любого изменения, включая переход состояния. `version` — опубликованная метка `major.minor.patch`, например `1.0.0`. Новая версия должна быть больше предыдущих. Метку нельзя перепривязать, перезаписать или удалить. Точное чтение: `get_library_item(item_id, revision=N)` либо `get_library_item(item_id, version="1.0.0")`; оба селектора одновременно запрещены.

Миграция SQLite v2 добавляет `library_heads`, `library_revisions`, `library_versions` без изменения таблиц/JSON старых проектов. Два встроенных персонажа и три фона регистрируются один раз как read-only версии `1.0.0` с прежними render references и снимком manifest. Voice aliases работают по старому механизму; ключи и окружение в библиотеку не копируются.

Ревизия хранится в SQLite и `.data/library/blobs/<sha256>.json`. Пакеты — там же. Оригинальные media находятся в `.data/assets/`; пакет содержит ссылки, хеши и измеренные метаданные без перерисовки и выдуманных таймингов. Чтение проверяет целостность ревизии, просмотр материалов и публикация — оригиналов. Публикация также проверяет подготовленный пакет.

Файл сбрасывается на диск до фиксации ссылки транзакцией. Сбой может оставить невидимый файл без ссылки, но не опубликованную половину результата. Голова и новая ревизия обновляются с `expected_revision` в одной транзакции; job и `preparing` создаются атомарно; результат job и `review` фиксируются вместе. Импорт, проигравший конкурентной правке, может оставить неиспользуемый immutable asset, но не меняет черновик.

## MCP-инструменты

| Инструмент | Назначение |
| --- | --- |
| get_submission_template | Шаблон, роли, ограничения |
| create_library_item | Создать запись с постоянным ID |
| update_library_item | Заменить описание новой ревизией |
| import_library_material | Импортировать или заменить роль |
| remove_library_material | Удалить роль из новой ревизии, сохранив исходник |
| get_library_item | Текущая или точная ревизия/версия |
| get_library_materials | Проверенные локальные ссылки для просмотра |
| list_library_items | Фильтры kind/state, limit 1–200, offset |
| list_library_versions | Опубликованные версии и номера ревизий |
| prepare_library_item | Идемпотентная подготовка в worker |
| get_environment_recipe_template | Шаблон слоёв, позиций героев и камер |
| set_environment_recipe | Сохранить разметку декорации новой ревизией |
| start_environment_test | Проверочный MP4 с двумя героями перед публикацией |
| publish_library_item | Выпустить проверенную локальную версию |
| archive_library_item | Архивировать без удаления истории |

Ошибки: `LIBRARY_NOT_FOUND`, `LIBRARY_VERSION_NOT_FOUND`, `LIBRARY_READ_ONLY`, `LIBRARY_STATE_CONFLICT`, `LIBRARY_VERSION_CONFLICT`, `LIBRARY_NOT_READY`, `LIBRARY_STORAGE_ERROR`, `LIBRARY_PREPARATION_FAILED`, `REVIEW_REQUIRED`; общие `REVISION_CONFLICT`, `IDEMPOTENCY_CONFLICT`, `VALIDATION_ERROR`, `ASSET_MISSING`, `CANCELLED`, `WORKER_INTERRUPTED`. В проверке пакета также `MATERIAL_REQUIRED` и `RIGHTS_REQUIRED`. Формат ошибок совпадает с остальными MCP-инструментами.

## Проверки

~~~powershell
./scripts/acceptance.ps1 -Library
# Полная регрессия существующего рендера:
./scripts/acceptance.ps1
~~~

На Linux: `bash scripts/acceptance.sh --library` (реальный Linux-прогон пока не выполнен).

Библиотечные проверки используют изолированную SQLite, явно обозначенный синтетический экран и двухсекундный звуковой тон. Это инфраструктурные fixtures, не настоящий эскиз или клонированный голос. WAV Microsoft Irina для этого режима не нужны. Проверяются миграция v1, шаблоны, stdio MCP, отдельный worker после закрытия MCP, конфликты, публикация/архив, хеши, запрещённый импорт, отмена, имитация истёкшей аренды и восстановление. Платные API не вызываются. Отчёт: `.data/acceptance-*/library/library-acceptance.json`.
