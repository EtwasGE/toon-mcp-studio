# Декорации: задачи 7–8

Декорации задаются JSON и работают в одном постоянном React/Remotion renderer. Три встроенных фона переведены в тот же формат. Имена декораций больше не определяют геометрию в JSX.

## Формат

- Холст 1080×1920, именованные слои с глубиной, безопасные векторные элементы либо маски над оригинальными PNG/JPEG.
- Позиции `left`, `right`, `center`: x, линия пола, масштаб, глубина и точка фокусировки. Их координаты относятся к ригу 380×560. Слой может находиться за героями, между ними или перед ними.
- Именованные `anchors` фиксируют пол, стол и другие ориентиры. Это метаданные для постановки; позы автоматически к ним не привязываются.
- Камеры `wide`, `two_shot`, `screen`, `close_up`. Крупный план наводится на фокус выбранного героя; `clamp` ограничивает сдвиг границами холста. Слои `world` следуют камере, `screen` остаются в координатах экрана. Независимый параллакс не реализован.
- `requires_cast` позволяет скрыть реквизит в сцене без героев.

Контракты: [environment](../contracts/environment.schema.json), [recipe](../contracts/environment-recipe.schema.json). Ограничения: 256 KiB, 512 узлов, 8 вложенных групп, 128 точек в маске. Произвольные HTML/JS, обработчики событий, внешние URL и CSS не принимаются. Структурная и семантическая проверки проверяют позиции, фокус, ссылки на внутренние SVG definitions и границы масок по измеренным размерам исходников.

## Подготовка из эскиза

1. Получить `get_submission_template(kind="environment")`. Пользователь присылает общий вид `wide` без героев; дополнительно доступны `layout`, `foreground`, `detail`. Готовое разбиение на слои не обязательно. Рекомендуемый исходник — 2160×3840; координаты масок задаются в пикселях фактического файла.
2. Создать `create_library_item`, импортировать материалы через `import_library_material`. Подтвердить права в submission.
3. Получить `get_environment_recipe_template`. Координаты примера подходят только [тестовой мастерской](../examples/environment-workshop/README.md).
4. Агент или художник размечает видимые объекты: `source_role`, `polygon`, `target:[x,y,width,height]`; настраивает глубины, позиции и камеры. Указать недостающие части в `missing_details`, добавленные детали — в `generated_details`, пояснения — в `notes`.
5. Сохранить `set_environment_recipe(item_id, expected_revision, recipe)` и запустить `prepare_library_item` с новой ревизией и ключом идемпотентности. Worker измеряет источники, проверяет маски, фиксирует bounding boxes и неизменяемые ссылки ассетов. Оригинальные пиксели не перерисовываются.
6. Прочитать ошибки/предупреждения и пакет через `toon://library/{id}/revisions/{revision}/package`. Неполная декорация не готова к публикации. Без recipe можно сохранить исходный пакет, но его `render_supported:false`.

Подготовка выполняется по явной разметке. Автоматическая нейросетевая сегментация, восстановление скрытого фона и достраивание новых ракурсов не реализованы. Если объект вырезан из единого фона, его исходное изображение остаётся на фоне; перемещать такую маску независимо без чистой фоновой подложки нельзя. Для такого движения нужен отдельный подготовленный фон и слой. Все необходимые дорисовки должны быть объявлены и просмотрены.

## Проверочный ролик и публикация

Зарегистрировать настоящую короткую речь (4–12 секунд) через `register_asset` и вызвать `start_environment_test`:

~~~json
{
    "item_id": "content_...",
    "expected_revision": 7,
    "audio_asset": { "asset_id": "asset_...", "version": "1.0.0" },
    "transcript": "Точный текст записи.",
    "idempotency_key": "workshop-test-v1"
}
~~~

Worker создаёт три сцены с двумя постоянными контрольными персонажами: общий план, крупный левого героя и крупный правого. Одна запись повторяется в трёх сценах; длительности берутся из аудио. Проба не вызывает платный TTS, продолжает работать после закрытия MCP, поддерживает `cancel_job` и публикует артефакты только после проверки MP4.

Просмотреть MP4 и контрольные PNG: маски перед героями, границы объектов, масштаб, линию пола, лица на крупных планах, отсутствие пустых краёв, субтитры. Прослушать речь и сверить transcript. `environment-review.json` оставляет художественный просмотр и прослушивание в `pending_operator`; технический успех их не подменяет.

Публикация через `publish_library_item(..., version="1.0.0", review_approved:true, review_note:"Что проверено")` требует успешный проверенный тест **того же package hash**. Правка recipe или материалов требует новой подготовки и новой пробы. Старая опубликованная версия сохраняется.

В обычной сцене использовать `background: {"asset_id":"content_...","version":"1.0.0"}`. Каталог `get_catalog(kind="backgrounds")` содержит встроенные и опубликованные версии. Snapshot фиксирует декорации по ключу `id@version`; export ZIP содержит определения и оригинальные изображения. В пробе неопубликованного пакета служебная версия `0.0.0`; перед обычным рендером заменить её на опубликованную.

## Воспроизводимая проверка

~~~powershell
# Python с Pillow; исходная PNG уже включена в репозиторий:
python scripts/create-environment-fixture.py examples/environment-workshop/wide.png
./scripts/acceptance.ps1 -Environments
~~~

На Linux доступен `bash scripts/acceptance.sh --environments`; реальный Linux-прогон остаётся pending. Проверка использует оригинальный synthetic fixture и локальную речевую SAPI fixture Microsoft Irina. Она не подтверждает качество настоящих присланных эскизов, клонирование голоса или живой ElevenLabs. Отчёт сохраняется в `.data/acceptance-*/environment-acceptance.json`.
