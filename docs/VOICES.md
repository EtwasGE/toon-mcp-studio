# Голоса персонажей: задачи 9–11

Реализованы импорт и техническая проверка записи, ElevenLabs Instant Voice Cloning, аудиопроба, одобрение и версионируемая привязка к персонажу. Клонирование и TTS выполняет постоянный worker. Закрытие stdio MCP не завершает worker и не отменяет очередь. Voicebox не используется.

## Подготовка записи

Заполните [шаблон голоса](../templates/library/voice.json). Укажите имя говорящего, язык, манеру речи и заметки о произношении. `rights_confirmed`, `details.cloning_consent` и `details.cloud_upload_consent` подтверждаются владельцем записи/голоса отдельно. Эти флаги не отправляют запись в облако сами по себе.

Импортируйте WAV или MP3 одного говорящего через обычный библиотечный процесс:

1. `create_library_item(submission)` с `kind="voice"`.
2. `import_library_material(item_id, expected_revision, role="sample", source_path)`; путь должен находиться в `TOON_IMPORT_ROOTS`.
3. `prepare_library_item(item_id, expected_revision, idempotency_key)` и ожидание `get_job`.
4. `get_library_item` / `get_library_materials`, затем чтение пакета `toon://library/{id}/revisions/{revision}/package`.

После каждого изменения берите возвращённую ревизию. Подготовка сохраняет оригинал и его SHA-256; нормализованная PCM-копия используется только для измерений. В облако уходит оригинальный файл. Удаление фонового шума выключено.

`voice_analysis` содержит длительность, peak/RMS dBFS, долю перегруженных сэмплов и тихих окон по 20 мс. Локальные технические пороги: запись от 10 секунд, RMS не ниже 0.005, доля тихих окон не более 85%, доля сэмплов с амплитудой ≥0.999 не более 0.5%. Это наши эвристики, не требования ElevenLabs. Рекомендуется 60–120 секунд чистой речи; общий лимит импорта по умолчанию 120 секунд и 25 MiB.

Анализ не распознаёт речь, число говорящих, музыку, право на голос или сходство будущего клона. Исходник необходимо прослушать. Заметки `pronunciation_notes` сохраняются как материал для оператора; автоматическая генерация словаря произношения не выполняется. Пакет исходников может быть опубликован локально даже при неудовлетворительном сигнале; клонирование блокируется, пока `voice_analysis.technical_ready` не станет `true`.

## Ключ и разрешения

В Visual Studio: **Toon.Worker → Управление секретами пользователя**. Общее хранилище `.NET User Secrets` имеет ID `toon-mcp-studio`, поле `ELEVENLABS_API_KEY`. Переменная окружения с тем же именем имеет приоритет. Ключ не попадает в JSON проектов, SQLite, экспорт или логи. `doctor` показывает только наличие ключа. Offline acceptance отключает User Secrets.

Для клонирования нужны одновременно серверные настройки в окружении MCP и worker:

```powershell
$env:TOON_ALLOW_VOICE_CLONING = '1'
$env:TOON_MAX_VOICE_CLONES = '1'
```

Это пример для одной **разрешённой оператором** попытки; наличие ключа не включает режим автоматически. `TOON_MAX_VOICE_CLONES` — общий накопительный предел отправок в текущем `TOON_DATA_ROOT`, не месячный лимит. Отклонённые и неопределённые запросы тоже учитываются. Для следующей согласованной попытки предел увеличивается явно. Удаление базы или смена data root сбрасывают локальный учёт, поэтому ограничение расхода API-ключа в ElevenLabs остаётся независимым барьером.

## Клонирование и аудиопроба

После прослушивания и подтверждения согласий:

```json
{
    "item_id": "ID_ИЗ_БИБЛИОТЕКИ",
    "expected_revision": 3,
    "allow_cloud_upload": true,
    "max_clone_requests": 1,
    "sample_reviewed": true,
    "review_note": "Один говорящий, запись прослушана, согласие подтверждено",
    "idempotency_key": "vasya-voice-1"
}
```

Передайте объект в `start_voice_clone`. Успешный `get_job` возвращает `result.profile` с `profile_id`, `revision` и `voice_id`. Наличие provider ID ещё не означает одобрение качества. `list_voice_profiles` показывает последние ревизии; `get_voice_profile` читает последнюю или точную ревизию.

Состояния:

| Состояние | Следующий шаг |
| --- | --- |
| `verification_required` | Пройти проверку в ElevenLabs и вызвать `refresh_voice_verification(profile_id, expected_revision)` |
| `pending_review` | Сгенерировать короткую аудиопробу и сравнить её с оригиналом |
| `approved` | Голос разрешено привязывать к персонажу |
| `rejected` | Рендер с этим профилем заблокирован; повторная аудиопроба и новое одобрение могут его вернуть |

`start_voice_preview` принимает `profile_id`, `expected_revision`, `text` (1–240 символов), `idempotency_key`, `allow_new_tts` и `max_new_tts_characters`. Для нового синтеза нужны `allow_new_tts=true` и достаточный лимит в пределах `TOON_MAX_TTS_CHARACTERS`; для кеша разрешены `false` и `0`. Завершённая задача публикует `voice-preview.wav` и `voice-preview.json` с измеренной длительностью и хешем.

Прослушайте пробу и вызовите `review_voice_profile(profile_id, expected_revision, approved, review_note)`. Одобрение требует успешную, не повреждённую WAV-пробу той же ревизии и отсутствие provider verification. Новая ревизия хранит решение оператора, а не автоматическую оценку сходства. Отклонение блокирует также старые ссылки на профиль. После повторного одобрения их можно использовать снова. Облачный голос при отклонении не удаляется.

## Привязка к персонажу

`bind_character_voice` принимает `character_id`, `version`, `expected_binding_revision`, `profile_id`, `profile_revision`. Для первой привязки `expected_binding_revision=0`; затем используйте ревизию из `get_character_voice(character_id, version)`. Персонаж должен иметь опубликованный render-compatible риг; встроенные `buyer@1.0.0` и `advisor@1.0.0` тоже поддерживаются.

В репликах проекта укажите:

```json
{
    "mode": "tts",
    "voice_alias": "character",
    "delivery": "neutral"
}
```

При создании/обновлении проекта система добавит `characters[].voice_profile` с конкретными `profile_id` и `revision`. Смена привязки влияет на будущие проекты, но не переписывает сохранённые. Чтобы заменить голос в новой ревизии существующего проекта, удалите прежнее `voice_profile` у нужного персонажа перед `update_project` или явно передайте новую одобренную ссылку. Обычные алиасы из `TOON_VOICE_ALIASES` продолжают работать независимо.

Для всех новых аудиопроб и озвучек используется **Eleven V4** (`eleven_v4`), включая алиасы. Запрос: `POST /v1/text-to-dialogue/with-timestamps`, один `inputs` на реплику, `language_code="ru"` (русский); формат MP3 44.1 kHz / 128 kbps. Автоматической замены модели при ошибке нет. Передаются только stability (по умолчанию 0.5) и similarity (0.75). Поле приложения `similarity_boost` преобразуется в `settings.similarity`. Прежние style, speed и speaker boost остаются в исторических настройках, но в V4 не отправляются и в новый ключ кеша не входят.

Модель, язык и эффективные настройки входят в ключ аудиокеша, поэтому пробы V2 не считаются пробами V4. Для прежнего одобренного профиля нужна новая прослушанная и одобренная проба V4. Исторические задания и файлы не переписываются. Финальный таймлайн считается по декодированному аудио; word timing берётся только из проверенной разметки провайдера, рот остаётся приблизительным движением по амплитуде.

Контракт: [ElevenLabs Models](https://elevenlabs.io/docs/overview/models), [Dialogue with timestamps](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert-with-timestamps). Живая генерация V4 пока не проверена; смена модели сама по себе не запускает платный запрос.

## Настройка подачи без повторного клонирования

`configure_voice_profile(profile_id, expected_revision, voice_settings, note)` сохраняет новую локальную ревизию, не обращается к ElevenLabs и не меняет `voice_id`. Для совместимости MCP принимает все пять полей; в V4 действуют только `stability` и `similarity_boost`:

```json
{
    "stability": 0.3,
    "similarity_boost": 0.85,
    "style": 0.6,
    "use_speaker_boost": true,
    "speed": 0.7
}
```

Допустимые диапазоны: `stability`, `similarity_boost`, `style` — 0–1; `speed` — 0.7–1.2; `use_speaker_boost` — boolean. Это пример для следующей аудиопробы, а не гарантия хрипоты или сходства. [Документация настроек](https://elevenlabs.io/docs/api-reference/voices/settings/update) описывает их влияние; [справка темпа речи](https://elevenlabs.io/docs/help-center/product/core-capabilities/text-to-speech/can-i-change-the-pace-of-the-voice) подтверждает используемый диапазон скорости.

Изменение сбрасывает одобрение в `pending_review`; незавершённая проверка провайдера сохраняет `verification_required`. Старые ревизии и ссылки проектов неизменны. Вызовите `start_voice_preview` с новой ревизией и отдельно разрешённым лимитом TTS, прослушайте пробу, затем выполните `review_voice_profile` и обновите привязку персонажа. Проба с прежними настройками не подходит для одобрения новой ревизии; изменённые настройки создают другой ключ аудиокеша.

## Сбои и отмена

Повтор `start_voice_clone` с тем же idempotency key возвращает ту же задачу. Дополнительно журнал связывает операцию с `item_id` и хешем образца: новый ключ или ревизия того же исходника не вызывают скрытую повторную отправку после неопределённого исхода.

При timeout, разрыве соединения, HTTP 5xx или некорректном успешном ответе возвращается `PROVIDER_OUTCOME_UNKNOWN`. Найдите голос в своём ElevenLabs и вызовите `reconcile_voice_clone(job_id, provider_voice_id, note)`. Новые запросы сохраняют полный маркер `[toon_request:clone-<SHA256>]` в конце `description`, после двух переводов строки; исходное описание и маркер не обрезаются. GET-проверка требует точного конечного маркера нашей операции; для ранее отправленных запросов также принимается совпадающий `labels.toon_request`. Несвязанный голос не принимается. Отсутствие маркера и старой метки требует ручного разбора; автоматический повтор POST запрещён.

Служебное поле `labels` больше не отправляется: провайдер отклонил его с `invalid_labels`. [Документация создания IVC](https://elevenlabs.io/docs/api-reference/voices/ivc/create) не публикует численный предел длины `labels` или `description`, поэтому конкретный предел длины не считается установленной причиной ошибки. `description` доступно и при [GET-проверке голоса](https://elevenlabs.io/docs/api-reference/voices/get). Локальная схема допускает исходное описание до 4000 символов; маркер добавляется отдельно, а совместимость такой предельной длины с живым API пока не проверена.

`cancel_job` до отправки предотвращает загрузку. После отправки отмена прерывает ожидание HTTP и локальные процессы, но не может гарантировать отмену облачной операции или списания. Незавершённый результат не публикуется как готовый. HTTP 4xx сохраняются как отклонение; новый явно созданный запрос допустим после исправления причины и истечения `Retry-After`. Изменение записи/согласий после постановки в очередь проверяется worker до отправки. Отзыв согласия блокирует дальнейшее использование профиля, но не удаляет уже созданные MP4.

Контракт провайдера: [Create IVC voice](https://elevenlabs.io/docs/api-reference/voices/ivc/create), [Get voice](https://elevenlabs.io/docs/api-reference/voices/get). Публичный endpoint фиксирован; образец и проект не могут подменить адрес отправки ключа.

## Запуск и проверки

```powershell
dotnet restore Toon.slnx --locked-mode
dotnet build Toon.slnx --no-restore
dotnet src/Toon.Worker/bin/Debug/net10.0/Toon.Worker.dll
# В другом терминале:
dotnet src/Toon.Cli/bin/Debug/net10.0/Toon.Cli.dll doctor
```

Offline-проверки:

```powershell
./scripts/acceptance.ps1 -Voices
dotnet tests/Toon.Acceptance/bin/Debug/net10.0/Toon.Acceptance.dll --secrets
```

Голосовой тест использует подставной HTTP transport, явно обозначенную локальную SAPI-речь и реальный рендер. Он проверяет импорт, отказы, согласия, лимит, идемпотентность, verification, аудиопробу, пересмотр решения, версии, кеш, отмену после отправки, Retry-After, восстановление по метке и MP4 независимого worker после закрытия MCP. Он не доказывает качество клона.

Отдельный **платный opt-in**, только после разрешения оператора:

```powershell
dotnet tests/Toon.Acceptance/bin/Debug/net10.0/Toon.Acceptance.dll --live-tts 1000
```

Выбирает два доступных готовых мужских голоса под героев примера, озвучивает существующий сценарий и проверяет финальный MP4; клонирование не выполняется. Отчёт и разрешённый предел сохраняются в отдельном `.data/acceptance-*/live-tts-*.json`. Для повторной проверки из кеша можно явно задать `TOON_DATA_ROOT` существующего live-прогона; по умолчанию создаётся новый каталог. Каждый запуск создаёт новый проект и задачу, поэтому после сбоя не повторяйте команду автоматически: сначала проверьте журнал и остаток согласованного бюджета. Фактические списания проверяются отдельно в ElevenLabs.

Живое клонирование остаётся pending до предоставления настоящего образца, подтверждения согласий и отдельного разрешения на отправку. Прослушивание и сходство требуют явного решения человека. Настоящий интерфейс рекламного примера также pending; тестовый экран помечен как учебный.


### Разметка V4 и сохранение полученного ответа

После получения ответа сохраняются аудио, его SHA-256, исходные alignment-массивы, текст и модельные настройки. Повторная локальная обработка уже полученного ответа не отправляет новый TTS-запрос. Границы слова вычисляются по буквам/цифрам провайдера; время завершающей пунктуации не растягивает произнесённое слово. Некорректная пословная разметка помечается как недоступная: проверенное аудио остаётся пригодным для режима `auto` с субтитрами всей реплики, но не выдаётся за точный word timing. `word`-субтитры и word anchors по-прежнему требуют валидных интервалов. В метаданных пробы это явно отмечено `timing_status=unavailable_utterance_only`.
