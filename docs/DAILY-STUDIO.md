# Ежедневный выпуск через Codex и Remotion Studio

## 1. Запустить студию

PowerShell 7, корень репозитория:

```powershell
./scripts/studio.ps1 -Profile alkash -TtsLimit 100000
```

Профиль `alkash` использует уже существующую библиотеку `.data/codilya-reference/runtime`. `default` использует `.data`. Для своей библиотеки: `-Profile my-show -DataRoot .data/workspaces/my-show -ImportRoots F:/materials`. Относительные пути библиотек и корней импорта отсчитываются от репозитория. Профили сохраняются локально в `.data/studio-profiles`, без ключей. Повторный запуск использует сохранённые настройки и работающий worker. Если зависимости ещё не установлены, сначала `./scripts/studio.ps1 -Setup`.

Скрипт проверяет зависимости, запускает скрытый самостоятельный worker, ждёт heartbeat и регистрирует MCP `toon-<profile>` через установленный `codex mcp add`. Для проверки без изменения Codex: `-NoConnectCodex`. После регистрации откройте новую сессию Codex и явно укажите нужный MCP. Старый `toon` не удаляется. Нельзя смешивать ID и проекты из разных библиотек.

Запуск не вызывает ElevenLabs. Число 100000 — технический накопительный потолок этого хранилища, а не тариф или оценка стоимости. Используйте его только в рамках ранее разрешённого режима; без `-TtsLimit` новый профиль запрещает новый TTS. Для каждого задания остаются `allow_new_tts` и `max_new_tts_characters`. Уже снятый пользователем предел 1000 не восстанавливается. Клонирование в ежедневном запуске отключено: для нового выпуска используется существующий голос. Ключ читается из User Secrets или окружения; его нельзя передавать в сценарии.

Если живой worker имеет другую сборку, корни или лимиты, запуск сообщит об этом и не прервёт его задания. Дождитесь завершения очереди, остановите именно этот worker и повторите запуск. При обновлении сборки также сначала остановите worker: Windows блокирует загруженные DLL.

## 2. Дать задачу Codex

Пример сообщения:

> Используй toon-alkash. Создай отдельный выпуск «Алкаш заказывает интернет-магазин», вертикальный, около 40 секунд. Используй Алкаша и опубликованные декорации из каталога, его одобренный голос. Сначала предложи реплики и планы. После согласования подготовь start_studio_preview и открой возвращённый open_studio_preview URL. Eleven V4, ru, Stability 0.5, Similarity 0.75. Голос повторно не клонируй.

Codex вызывает `get_episode_template`, выбирает точные ID/версии из каталогов и формирует короткий brief. Пользователю не нужно писать JSON. Шаблон для ручной работы: `templates/episode.json`, контракт: `contracts/episode.schema.json`. В нём только название, герои, сцены и реплики; можно задать запись вместо TTS, жест, эмоцию, крупный план и паузу. Одна сцена показывает 1–2 героев. Target 20–45 секунд служит ориентиром; максимальная фактическая длина 60 секунд, речь не подрезается ради target.

`create_episode(brief, idempotency_key)` создаёт новый проект и фиксирует одобренные голоса. Повтор с тем же ключом и brief возвращает первый проект; другой brief с тем же ключом отклоняется. Создание не генерирует речь. `list_projects` возвращает последние ревизии с названиями и поддерживает limit/offset.

`update_episode(project_id, expected_revision, brief)` сохраняет новую ревизию **всего** короткого сценария. Для сложных экранов телефона, overlays и событий используйте `get_project` → `update_project`: эти детали не представлены коротким brief и при его полной замене не сохраняются.

## 3. Предпросмотр до MP4

1. `validate_project` показывает ошибки и количество новых TTS-символов.
2. `start_studio_preview(project_id, revision, idempotency_key, allow_new_tts, max_new_tts_characters)` ставит подготовку в очередь. Записи/кеш: `false`, `0`. Новая речь — только разрешённый объём.
3. После `get_job` → `succeeded`, `open_studio_preview(job_id)` проверяет хеши комплекта и возвращает адрес `http://localhost:PORT/Toon`. Codex открывает **этот** адрес в браузере.
4. Studio показывает настоящие изображения, субтитры, таймлайн и звук. Можно проигрывать и перематывать. Здесь ещё нет MP4; результат обозначен `studio_preview`, `video_exported=false`.

Предпросмотр использует общий renderer и файлы конкретной ревизии. Для props используется файл, как рекомендует [Remotion для Windows](https://www.remotion.dev/docs/options/props); ассеты подаются из отдельного [public directory](https://www.remotion.dev/docs/options/public-dir). Пакеты остаются закреплены на 4.0.538. HTTP слушает только 127.0.0.1. Параметр `--editor vscode` обходит зависающее на этой Windows автоматическое определение редактора; для просмотра наличие VS Code не требуется. Встроенный `open in editor` не является редактором проекта Toon.

Правки делайте сообщениями Codex: «во второй сцене крупный план», «пауза после первой реплики 600 мс». Codex сохраняет новую ревизию и подготавливает новый preview; неизменённая речь берётся из кеша. Прямые изменения в интерфейсе Remotion **не записываются обратно в SQLite**. Каждый URL привязан к конкретной ревизии; открытие старого URL продолжает показывать старую ревизию.

`close_studio_preview(job_id)` останавливает только соответствующий сервер по PID и времени запуска. Проект, звук и worker остаются. Повторное открытие запускает Studio заново. Перед открытием после изменения renderer требуется новый preview.

Без Codex, для существующих записей/кеша:

```powershell
./scripts/studio.ps1 -Profile alkash -Brief ./my-episode.json -EpisodeKey my-show-001 -Preview -Open
# Или уже сохранённый проект:
./scripts/studio.ps1 -Profile alkash -ProjectId project_ID -Revision 2 -Preview -Open
# Открыть подготовленное задание:
./scripts/studio.ps1 -Profile alkash -JobId job_ID -Open
```

Для заранее разрешённого нового синтеза добавьте `-TtsCharacters N`; N — положительный лимит данного задания, не больше сохранённого server limit. Без этого параметра используются только записи и кеш. Закрытие Codex/MCP не останавливает worker и сервер предпросмотра.

## 4. Получить финальный ролик

После правок попросите Codex выполнить `start_render` для **той же принятой ревизии**, `quality="final"`. Для подготовленной озвучки обычно достаточно `allow_new_tts=false`, `max_new_tts_characters=0`. Финальный путь выполняет нормализацию громкости, кодирование, проверку целостности и публикацию MP4. Кнопка Render в Remotion не заменяет эти проверки Toon.

В `<data_root>/artifacts/<job_id>/` будут MP4, проект, timeline, субтитры, обложка, отчёт и ZIP. Просмотрите результат и прослушайте окончания фраз. Предпросмотр использует исходный микс; финальная нормализация применяется при экспорте MP4. Движение рта остаётся приблизительным, по амплитуде.

Проверка использует явно обозначенные речевые SAPI fixtures, отдельный worker и настоящий MCP; оплачиваемые запросы не выполняются. Linux/WSL отдельно не проверен. Результат и URL: `.data/acceptance-*/studio-acceptance.json`.
