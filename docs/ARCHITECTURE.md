# Устройство реализации

`ContentWorkflows` объединяет операции в четыре читаемых MCP-сценария: character, environment, voice, production. Инструмент и JSON resource возвращают одинаковую последовательность; шаблоны используют тот же источник. Markdown-руководство доступно как resource, поэтому агент не зависит от памяти предыдущего разговора. Эти описания не выполняют изменения автоматически: каждый переход и платная операция сохраняют собственные условия, ревизии и разрешения. Сквозной acceptance-клиент проверяет реальные tools/call и resources/read, а не вызывает бизнес-методы вместо пользовательского пути; исключение — явно внедрённый offline HTTP transport внутри тестового voice-worker.

MCP работает поверх официального SDK: stdio transport, tools, resources и structured error union. JSON-RPC вручную не реализован. Логи host направлены в stderr. Media subprocess получает закрытый stdin и не получает ключ ElevenLabs: он не может читать протокол MCP. CLI — настоящий SDK MCP client, а не прямой вызов классов.

Core проверяет оригинальную JSON Schema 2020-12 и связи внутри проекта: IDs, видимый cast, camera subject, каталоги, локальность anchors. Compiler использует последовательную sample-based шкалу 48 кГц, измеренную после декодирования. Интервалы `[start_frame,end_frame_exclusive)`, midpoint away from zero, финальный ceiling. Пауза после последней реплики не теряется. Он проверяет интервалы, коллизии каналов cue, длительность переходов, привязки слов и 1800-frame limit.

Infrastructure отвечает за SQLite, immutable asset registry, копии медиа, анализ речи, ElevenLabs, процессы, микс и верификацию. Revision записывается транзакционно с compare-and-swap `expected_revision`. Источник истины — SQLite; JSON в projects — экспортируемая копия. Короткие транзакции WAL, busy timeout 10 s. Lease получает ровно один worker; file lock предотвращает два worker для одного root. Recovery не обещает продолжение произвольного кадра: новый job повторяет рендер, используя пригодный кеш.

Job snapshot фиксирует revision, assets/hash/version, resolved voices, параметры расходов и fingerprint исходников рендерера/пакетов/стиля. Изменённая после enqueue установка даёт ошибку версии. Аудио кеш хранит source hash, prepared PCM, sample count, amplitude envelope, alignment и параметры синтеза. Файл кеша проверяется по hash; неоднозначный provider request блокирует повтор того же ключа до ручной сверки. Это at-most-one-dispatch после неизвестного исхода, а не обещание exactly-once внешнего API.

Платные обращения запрещены в обычных тестах. Mock HTTP tests изолированно передают `HttpClient` в адаптер; production URL не конфигурируется входным проектом. Тесты помечены fixtures и не доказывают реальную доступность модели, качество голоса или списание.

Renderer содержит общий React/SVG интерпретатор декларативных ригов, три фона, четыре плана и семь жестов. Риги двух встроенных героев хранятся в JSON; подготовленные библиотечные персонажи используют тот же компонент. Состояние — чистая функция frame/seed; микродвижения и моргание независимы. При speech рот активен только у соответствующего speaker, по его исходной огибающей до музыкального микса. Выражение эмоции сохраняется в бровях/глазах; рот речи имеет приоритет. Файл font загружается явно; browser layout проверяет число строк. Preflight fontkit проверяет glyph coverage, максимальное слово и safe-area высоту оверлеев.

Remotion создаёт видеоряд. FFmpeg собирает голосовые дорожки с `adelay` в сэмплах, а не покадровым накоплением округлений. Музыка, если импортирована, циклична, имеет заданный gain и sidechain ducking от суммарной речи. Loudnorm в два прохода, запас по true peak. Проверка готового MP4 включает ffprobe, полное декодирование с `-xerror`, размер/fps/кодеки, длительность и измерение громкости. Только после неё publisher перемещает подготовленный комплект и записывает artifact metadata в транзакции, проверяющей cancellation.

PNG-контрольные кадры берутся до H.264 на границах сцен/cue и внутри жестов, в полном разрешении для обоих профилей. Это позволяет сравнить детерминизм в закреплённом окружении. Побайтовая идентичность MP4 между платформами не обещается.

## Что не является автоматической гарантией

Наличие записанного transcript не доказывает смысловое совпадение со звуком; ASR не включён. Амплитуда не даёт фонем. `exact` не доказывает читаемость мелкого текста на телефоне. Автоматический layout не заменяет проверку всех художественных пересечений рук/лиц/телефона. SAPI fixtures не подтверждают доступность двух выбранных облачных голосов. Независимый Windows-run не подтверждает Linux/WSL.

## Форматы

Библиотека контента использует миграцию SQLite v2, content-addressed JSON и тип задания `library_prepare` в общей очереди worker. Ревизии, версии и состояния описаны в [CONTENT-LIBRARY.md](CONTENT-LIBRARY.md). DraftProject 1.0.0 получил необязательное поле `characters[].voice_profile`; существующие проекты совместимы. Source packages не выдаются за поддерживаемые рендерером риги. Секреты и voice aliases из окружения в библиотеку не копируются.

Входные схемы: `contracts/project.schema.json`, `contracts/audio-alignment.schema.json`. Derived contracts: `contracts/timeline.schema.json`, `contracts/job.schema.json`, `contracts/artifact.schema.json`. Содержимое production sidecar проверяется поверх схемы: непрерывные индексы, transcript, display spans, реальные пределы PCM и монотонность. Illustrative `example_only:true` запрещён. Схема не заменяет семантическую проверку.

Добавление стиля требует доверенных компонентов, нового versioned manifest, DIRECTING и QA. Динамическая загрузка пользовательского кода не поддерживается. Изменяйте renderer version при несовместимой геометрии/таймлайне и повторяйте визуальные проверки.

Декорации используют `environment.schema.json` и `environment-recipe.schema.json`. `EnvironmentStage` сортирует слои и персонажей по глубине; позиции, масштаб, линия пола и камеры берутся из данных. Worker заменяет роли исходников масками над immutable assets. Snapshot и timeline сохраняют определения по ключу `id@version`; экспорт включает исходные изображения. `start_environment_test` создаёт обычное render-задание с двумя контрольными героями. Публикация renderable-декорации требует проверенный MP4 для того же package hash и явное review. Подробности: [ENVIRONMENTS.md](ENVIRONMENTS.md).


Голосовые профили используют миграцию SQLite v3: `voice_profiles` и `character_voices` с неизменяемыми ревизиями и проверкой SHA-256. `voice_clone` и `voice_preview` выполняются в общей очереди worker. Бюджет клонирования и состояние отправки резервируются транзакционно в `provider_requests` до HTTP. Неопределённый исход не повторяется; восстановление требует точной метки операции в метаданных провайдера. Старые проекты сохраняют выбранную ревизию, но текущее отклонение профиля или отзыв согласия блокирует дальнейший рендер. Подробности: [VOICES.md](VOICES.md).

Ключ берётся централизованно из окружения или общего .NET User Secrets. Offline acceptance отключает User Secrets; явный `--live-tts` — отдельный платный opt-in с ограниченным бюджетом. Диагностика не возвращает ключ, ошибки чтения secrets.json не включают содержимое файла.
